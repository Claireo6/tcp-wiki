# CUBIC for Fast and Long-Distance Networks

Category: Standards Track
Obsoletes: 8312
Updates: 5681

## 文件基本資訊
- **編號**：RFC 9438
- **作者**：L. Xu（UNL）、S. Ha（Colorado）、I. Rhee（Bowery）、V. Goel（Apple Inc.）、L. Eggert（編輯，NetApp）
- **日期**：August 2023
- **頁數**：本 RFC 採新版格式，純文字檔沒有頁碼，因此不記錄頁數。
- **地位**：Standards Track；取代 RFC 8312，並**正式更新 RFC 5681**。這是 raw/ 中第一份對 RFC 5681 有正式 `Updates` 關係的文件，因此兩者差異依規則視為「演進」，記錄在 [時間軸](../timeline.md) 與概念頁的「歷史演進」小節。
- **名稱查證**：本文件把 RFC 5681、NewReno 等使用線性增長的標準統稱為「Reno」[RFC 9438 §1]。全文未出現 Tahoe。

## 背景與動機
CUBIC 已是 Linux、Windows 與 Apple 協定堆疊的預設 TCP 壅塞控制演算法 [RFC 9438 §1]。

> CUBIC has been adopted as the default TCP congestion control algorithm in the Linux, Windows, and Apple stacks, and has been used and deployed globally. [RFC 9438 §1]

設計動機是 Reno 在高速、長距離網路中利用率偏低：在頻寬延遲乘積（BDP）很大的網路裡，壅塞事件之後 `cwnd` 增長太慢 [RFC 9438 §1]。

> This problem arises from a slow increase of the congestion window (cwnd) following a congestion event in a network with a large bandwidth-delay product (BDP). [RFC 9438 §1]

## 對 RFC 5681 的更新
CUBIC 在 congestion avoidance 階段可能比 Reno 更積極地增加 `cwnd`（RFC 5681 規定每個 RTT 不得超過 `SMSS`），且建議 slow start 改用 HyStart++；因此本文件更新 RFC 5681 以允許這些行為 [RFC 9438 §1]。

> Specifically, CUBIC may increase the congestion window more aggressively than Reno during the congestion avoidance phase. [RFC 9438 §1]

## 四個設計原則（§3）
1. **先凹後凸的增長**：使用三次函數的凹段與凸段增加視窗 [RFC 9438 §3.1]。
2. **對 Reno 友善**：在 RTT 短、頻寬小、Reno 表現良好的網路中，行為與 Reno 相近 [RFC 9438 §3.2]。
3. **RTT 公平性**：不同 RTT 的流量，頻寬分配與 RTT 比值呈線性關係 [RFC 9438 §3.3]。
4. **乘法減少係數 0.7**：在擴展性與收斂速度之間取得平衡；Reno 使用 0.5 [RFC 9438 §3.4]。

> To achieve a balance between scalability and convergence speed, CUBIC sets the multiplicative window decrease factor to 0.7, whereas Reno uses 0.5. [RFC 9438 §3.4]

## 限制
CUBIC 與 Reno 一樣以封包遺失判斷壅塞；在封包遺失不能代表頻寬使用狀況的網路（如無線或行動網路）表現較差 [RFC 9438 §5.4]。由於增長更積極，也可能更快填滿大型緩衝區，增加形成持續性佇列的風險 [RFC 9438 §5.4]。

> Similar to Reno, the performance of CUBIC as a loss-based congestion control algorithm suffers in networks where packet loss is not a good indication of bandwidth utilization, such as wireless or mobile networks [RFC 9438 §5.4]
