## 文件範圍
本文件定義 TCP 四個相互交織的壅塞控制演算法：slow start、congestion avoidance、fast retransmit 與 fast recovery；這些演算法源自 [Jac88] 與 [Jac90]（即 Jacobson 的研究）[RFC 5681 §1]。此外也規範閒置過久後如何重新開始傳送，以及 ACK 的產生方式 [RFC 5681 §1]。

TCP 可以比本文件的演算法更保守，但**不得更激進**（MUST NOT be more aggressive）[RFC 5681 §3]。本文件的演算法以「封包遺失」作為壅塞信號 [RFC 5681 §3]：

> Also, note that the algorithms specified in this document work in terms of using loss as the signal of congestion. [RFC 5681 §3]

## 重要定義（§2）
- `SMSS`：傳送端可送出的最大區段大小，不含 TCP/IP 標頭與選項 [RFC 5681 §2]。
- `rwnd`：接收端最近一次通告的接收視窗 [RFC 5681 §2]。
- `cwnd`：限制 TCP 可送出資料量的狀態變數 [RFC 5681 §2]。
- `IW` / `LW` / `RW`：分別為三向交握完成後、重傳計時器偵測到遺失後、閒置後重新傳送時的 `cwnd` 大小 [RFC 5681 §2]。
- `FlightSize`：已送出但尚未被累積確認的資料量 [RFC 5681 §2]。
- Duplicate ACK：需同時滿足 5 個條件（有未確認資料、ACK 不帶資料、SYN/FIN 皆為 0、確認號等於目前最大確認號、通告視窗不變）[RFC 5681 §2]。

> CONGESTION WINDOW (cwnd): A TCP state variable that limits the amount of data a TCP can send. [RFC 5681 §2]

## 主要內容摘要
1. **Slow start 與 congestion avoidance**（§3.1）：傳送量由 `cwnd` 與 `rwnd` 的較小者決定；`IW` 依 `SMSS` 大小上限為 2、3 或 4 個區段；`ssthresh` 初始值應設得任意高；逾時後 `ssthresh = max(FlightSize/2, 2*SMSS)`、`cwnd` 降為 1 個區段 [RFC 5681 §3.1]。詳見 [慢啟動](../concepts/slow-start.md) 與 [壅塞避免](../concepts/congestion-avoidance.md)。
2. **Fast retransmit 與 fast recovery**（§3.2）：收到 3 個 duplicate ACK 即重傳疑似遺失的區段，並以 6 個步驟調整 `cwnd` [RFC 5681 §3.2]。詳見 [快速重傳與快速恢復](../concepts/fast-retransmit-fast-recovery.md)。
3. **閒置連線重啟**（§4.1）：超過一個重傳逾時沒有傳送資料時，`cwnd` 不得超過 RW = min(IW, cwnd) [RFC 5681 §4.1]。
4. **ACK 產生**（§4.2）：建議使用 delayed ACK，但至少每兩個完整區段回一個 ACK，且最多延遲 500 ms [RFC 5681 §4.2]。
5. **進階遺失修復**（§4.3）：建議實作能處理「同一視窗多個遺失」的進階修復演算法，例如 RFC 3782（NewReno 的前一版）與 RFC 3517 [RFC 5681 §4.3]。
